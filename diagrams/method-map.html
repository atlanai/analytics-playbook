Why this exists. An agent can write clean SQL and still give the wrong number, because it guesses business rules nobody wrote down. The method writes those rules down, tests them on real questions and keeps them true, one business area at a time. Open any box to see what is inside it.

Phase 0 · ScopeBefore the clockBrief, bar, access proved
Step 0.1Pick one domainOne business area, its users and its numbers
HowChoose an area with real questions, known users and someone with time to settle its definitions.
Watch outThree areas at once give you three half-built answer keys and nobody with time for any.
Step 0.2Write the briefOne page everyone agrees on
HowUsers, the problem, the bar, and which numbers must be exact every time and which only need to point the right way.
TemplateDomain brief
Step 0.3Set the barOne pass rate, written before any result
HowOne bar for the whole golden set: a pass rate, met on every run. Write it in the brief. The running example uses 9 in 10.
WhoExec sponsor
Watch outA bar written after the first scores bends toward them.

Step 1.1Harvest real questionsFrom what the business already asks
HowCollect two or three times more than you need, from the board pack, dashboards, tickets and the sponsor. Write each the way a user asks it.
TemplateQuestion-harvest sheet
Step 1.2Write the answer keyThe right answer, and how you know
HowFor each question: the correct SQL, its answer, the source it was checked against, and the decisions the question hides.
TemplateGolden-set item
Step 1.3Agree how to gradeBefore any result exists
HowCheck the returned numbers first, then the SQL. Allow more than one valid answer. A refusal counts as a miss.
TemplateGrading rubric
Step 1.4Seal it from the buildersSo the agent can't learn the answers
HowStore it where the agent and the people building its context can't read it, and remove matching past queries from the context.
ChecklistThe eval owner's week

HowRun each question once on the bare tables, and note which decision the agent guessed on every miss.

Phase 2 · BuildGenerate metricsBusiness rules written as SQL
Step 2.1Gather past SQL and reportsWhat your company already knows
HowThe queries analysts actually ran, with who ran them and how often, plus the dashboards and semantic models leaders read.
Watch outLeave out the agent's own queries and scheduled machine traffic.
Step 2.2Generate candidate metricsDrafted from real queries
HowGroup queries that share one shape and name the metric inside each. A script or a tool can do it.
Watch outThe generator never sees the golden set, and every candidate keeps the real SQL it came from.
Step 2.3Test each against the warehouseNothing counts until it has run
HowRun each candidate read-only. Does it run? How many rows? Is each thing counted once? Hold back anything you can't explain.
Step 2.4Settle conflictsTwo versions of the same number
HowThe version most analysts ran recently, that matches the warehouse, usually wins. Whoever owns that number decides the rest.
WhoThe owner of that number; both owners when two teams share it
ChecklistHow to resolve a conflict
Watch outNever let the agent pick between two definitions.
Step 2.5Approve and serveApproved, versioned, handed to the agent
HowEach metric is approved with an owner and a version. Per question, the agent gets a handful of items as complete SQL.

Phase 3 · DebugHill-climb from tracesRead the trace of every miss
Step 3.1Read the raw traceEvery step the agent took
HowFor each wrong answer, open the step-by-step record: what it was given, and every query it ran. A summary hides the guess.
TemplateTrace review sheet
Step 3.2Find the kind of missThree kinds, one fix each
Never writtenThe rule exists nowhere. Write it down, and settle it if it is in dispute.
Written, not foundThe rule exists but never reached the agent. Fix how it is looked up.
Found, ignoredThe agent took a simpler path. Make the rule one it must follow.
ChecklistWhy did this miss?
Step 3.3Make the smallest fixOne metric, rule or word at a time
HowWrite down which questions the fix should repair, then change one metric, one rule or one word link.
Watch outFix the rule, never the answer. No sealed value may enter the context.
Step 3.4Rerun everythingA fix can break something else
HowRerun the whole set after every change. Keep the change only if nothing that passed has broken, and log it.
TemplateIteration ledger
Step 3.5Add questions before launchFresh questions for the launch test
HowGraders add new real questions that the people building the context never see, so the launch score is not one you tuned against.
Step 3.6Know when to stopDecided before the first round
HowStop when two rounds in a row barely move the score, or after five rounds, and report the ceiling honestly.
Watch outGiving the agent more steps turns honest refusals into confident wrong answers.
