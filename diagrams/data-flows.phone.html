1 · Result rowsFrom your warehouse to your harness, its model and your trace store; never through the context layer. Read under a named identity: the asking user, or a service account.
2 · Past SQL and BI definitions. Query text, BI reports and DDL, read by a read-only identity, go to the model the metrics agent uses. Query text only, never table rows. Security approves it in Phase 0; name the provider in the brief.
3 · Served contextThe context layer serves metrics, trusted past queries, rules and terms over MCP or API to the model your harness calls, per question: definitions, not data. Traces go back to your trace store and context layer.

Three flows, agreed with security in Phase 0. Every context call is traced.
