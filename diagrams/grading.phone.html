1. 1 · Does the returned data match? code grades it
    1. Against the expected result or a valid alternative, within tolerance: counts exact, amounts within 0.5%. A total or a breakdown summing to it both pass.
    2. noWrong on this run. Declined to answer is its own verdict, never right, reported apart from wrong.
  2. 2 · Does the SQL make the item's decisions? domain grader; a judge only once calibrated
    1. noWrong on this run. A wrong query can land near the right number by luck; a near-match of data alone never passes.
  3. 3 · Right on all k runs of the same configuration? code compares values and SQL
    1. noFails pass^k. Right on at least one run is pass@k; never quote it as accuracy.
  4. yesPass^k · the item counts. Report pass^k for the governed lane: a board number right on two runs of three is wrong. An item right on every run joins the regression set, and leaves it if it fails. The same setup, run twice, can disagree on a few questions.
