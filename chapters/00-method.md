[]{#lifecycle}[Why it is hard](#ch01-fixes) ends with four problems. It runs on any stack, with a warehouse, scripts and version control. Each stage below is one click from its chapter.

## What closes the gap {#ch02-ladder}

We took real questions our analysts had asked, sealed the correct answer to each one, and ran the same questions again, each time adding one kind of context to the bare schema.

::: {.diagram #ladder}
The same questions with bare schema alone, and with one kind of context added to it each time: descriptions and documentation, usage patterns from the query log, and AI-generated metrics with trusted past queries. <!-- E03 E16 E04 E52 -->
:::

Bare schema carries none of the decisions, and scored 31.8% <!-- E03 -->. Descriptions and documentation reached 39.3% <!-- E16 -->, a few points for about seven times the context. They say what a table holds, and the decisions aren't descriptions. Usage patterns mined from the query log, such as the filters and joins analysts actually use, served with the descriptions, reached 43.9% on an earlier version of the answer keys <!-- E04 -->. The big jump came from metrics served together with trusted past queries, all generated by our systems from the query log: 83.2% <!-- E52 --> on the configuration we ship. An analyst who ran the right query had already made the right decisions, and a metric seals them so they hold every time.

The rest of this page is how you build that last bar for your own domain: metrics generated from the SQL your analysts already run, tested against a golden set, one domain at a time.

## The lifecycle {#lc-cycle}

One analyst can get one agent through one set of questions with a long week of prompt edits. The next quarter, the next model or the next domain undoes most of it. Teams that ship software solved this problem years ago: write the tests first, build, debug against the tests, release behind a gate, operate. An analytics agent needs the same loop, with a golden set of real questions playing the part of the test suite.

::: {.diagram #lifecycle}
The lifecycle. Click a stage to open its chapter. Every stage is scored against the golden set at the centre, and the loop closes when the next domain starts from what this one built.
:::

Some teams spend a month on this loop and some do it in a week. The phases are an order, not a calendar.

## Eight rules {#rules}

The loop runs on eight rules. Rules 1, 2, 3 and 5 rest on our benchmark, and each links to its evidence. Rule 4 and the last three are what building and running the method taught us.

1. **Fix the context before you change the model.** Switching models moved our score far less than adding context: [the model chart](#ch01-models).
2. **Write each business rule into a metric's SQL.** The past queries your analysts already ran carry the rules, and a sentence leaves the agent to translate them: [SQL, not a sentence](#ch02-form).
3. **Build the golden set before any context.** Without sealed answers, you can't tell a fix from luck: [Evals first](#ch-evals).
4. **Settle conflicts before the agent sees them: provenance first, then the owner.** The definition most analysts ran recently, and that matches the warehouse, usually wins. A definition kept only in a spreadsheet leaves no query history, so whoever owns that number settles it. Never let the agent pick.
5. **Choose the lane by the use: exploratory or governed.** Exploratory answers suit questions where a person reads the SQL before acting on it. A number that goes on a board slide needs the governed lane: a metric that gives the same answer every time, or no answer: [Two lanes](#ch02-lanes).
6. **Start with one domain.** One domain is small enough to finish, and its open questions have someone who can settle them.
7. **Read the raw trace of every miss, and feed real usage back.** The summary hides the step where the agent guessed, and context left alone goes stale within a quarter.
8. **Make the agent reliable on what happened before you ask it why.** "What was pipeline last quarter?" needs metrics. "Why did it drop?" needs a model of how the business works on top of them, and it is only worth building once the numbers hold.

## The gates {#start-phases}

Each phase of the lifecycle ends at a gate. Move on when the gate is met, whatever the date.

Phase 0 runs before the clock: the clock is the build, and it starts with Phase 1, once Phase 0's gate is met. Phase 3 is the hill climb: run the golden set, read the trace of each miss, make the smallest fix and run it again. Phase 4 releases the agent and hands it over; [What you'll walk away with](#home-outcome) lists what your team holds at the end.

::: {.diagram #phases}
Five phases: Phase 0 to set up, then Phases 1 to 4 to build, test and launch, each ending at its gate. The golden set starts at 20 questions in Phase 1. During Phase 3 the graders add questions the context engineer never sees, first scored at the launch gate.
:::

Before Phase 1 you need read-only warehouse access, query history and BI reports. You also need your agent harness set up to record a trace of every run, so that your first test runs are traced. The full list is on [What you need before you start](#c11).
